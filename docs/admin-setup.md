# Admin Setup Guide

Shopify 管理画面（admin）でのみ完結する設定をまとめたガイド。テーマ側コードでは扱えない／扱わない部分です。

## 1. 商品にサイズ（ホールサイズ）バリアントを追加する

Phase 3b の `tab-size-guide` で表示している「3号〜7号」の目安と整合させるための設定。

### 手順

1. Shopify admin → **商品管理 / Products**
2. 対象商品（例：`strawberry-shortcake`）を開く
3. **バリエーション / Variants** セクションで「**オプションを追加 / Add an option**」
4. 以下のオプションを設定：

   | 項目 | 値 |
   |---|---|
   | オプション名 / Option name | `サイズ` |
   | オプション値 / Option values | `3号`, `4号`, `5号`, `6号`（カンマ区切りで入力） |

5. 各バリアントごとに価格・在庫を設定

### 推奨価格設定（Sweet Atelier ベース）

| サイズ | 直径 | 目安人数 | 推奨価格（税込）|
|---|---|---|---|
| 3号 | 9cm | 2〜3名 | ¥3,800 |
| 4号 | 12cm | 3〜4名 | ¥4,800 |
| 5号 | 15cm | 5〜6名 | ¥5,800 |
| 6号 | 18cm | 7〜8名 | ¥6,800 |

> 7号・8号は記念日商品（アニバーサリーコレクション）にのみ用意するのが運用上シンプル。

### 注意事項

- **在庫管理を有効にしている場合**：各バリアントごとに在庫数を設定（手作りケーキは「在庫を追跡しない / Don't track quantity」推奨）
- **重さ / Weight**：冷凍便の送料計算に影響するため正確に入力
- **SKU**：在庫管理する場合のみ（例：`SA-STRAWBERRY-04` = Sweet Atelier / イチゴ / 4号）
- **商品画像とバリアントの関連付け**：サイズ違いで写真が同じなら未関連でOK

### バリアントが追加できない商品

- ロールケーキ（`matcha-roll`）
- 焼き菓子ギフト（`baked-goods-gift`）
- カットケーキ・季節限定の単品商品

これらは `tab-size-guide` の補足文「※ ロールケーキ・焼き菓子・カットケーキ等は形状が異なるため『商品仕様』をご確認ください」で案内されます。

## 2. variant_picker の表示制御

テーマ側 (`templates/product.json`) で：

```json
"variant-picker": {
  "type": "variant_picker",
  "settings": {
    "picker_type": "button",  // "dropdown" or "button"
    "swatch_shape": "circle"
  }
}
```

- `picker_type: "button"` → サイズ選択は「3号 / 4号 / 5号 / 6号」のボタン横並び
- `picker_type: "dropdown"` → セレクトボックス
- ホールサイズはボタン推奨（タップ領域大きく、選択肢可視性高い）

main の `settings.hide_variants: true` でデフォルト Variant（バリアントなし商品）の picker を自動非表示にする挙動はそのまま。

## 3. コレクションへの商品追加

Phase 1 で作成済みのコレクション（signature / seasonal / anniversary / gifts / baked-goods）に新商品を追加する場合：

1. 商品ページ → **商品の整理 / Organization** → **コレクション / Collections** に追加
2. コレクションページで並び順を調整（手動 / アルファベット / 価格 / 新着等）
3. 公開状態 / Publication を **オンラインストア / Online Store** で公開に

## 4. お届け日・ギフトオプションの注文確認（Phase 3c / 3d）

Phase 3c で `properties[熨斗]` `properties[熨斗の用途]` `properties[熨斗の名入れ]` `properties[メッセージカード]` `properties[ギフトラッピング]`、Phase 3d で `properties[お届け希望日]` `properties[お届け時間帯]` を line item property として送信しています。

### 注文管理画面での確認

注文管理 → 注文詳細 → 各 line item の下に **追加情報 / Properties** として表示されます。フルフィルメント担当者が見る前提で、PDF 注文票・梱包伝票へのプリントレイアウトは別途調整が必要です(Shopify 標準では出力されないテンプレートあり)。

### Bogus Gateway でテスト注文

Phase 3 クロージング時に1件は流して以下を確認:

- properties が注文管理に正しく反映されること
- 受注メールに properties が出ること(`Order confirmation` メールテンプレート編集が必要なら admin → 設定 → 通知 から HTML/Liquid を調整)
- お届け日が水曜にならないこと(JS 側のバリデーションは送信時点では Shopify 側に届くので、注文を見て監査する運用)

## 5. 商品タグで「新商品 / 季節限定 / 人気」バッジを表示する（Phase 3e）

`snippets/card-product-extra-badge.liquid` がカード/PDP の price 表示にバッジを描画します。表示優先度は **popular > seasonal > new**(同時複数タグでも 1 つのみ表示)。sold-out / sale 時はそちらが優先され、タグバッジは非表示。

### 手順

1. 管理画面 → 商品管理 → 対象商品を開く
2. 右サイドバー **タグ / Tags** に以下のいずれかを追加:

   | タグ | 表示ラベル | 用途 |
   |---|---|---|
   | `new` | 新商品 | 入荷から 1〜2 ヶ月以内 |
   | `seasonal` | 季節限定 | 季節のケーキコレクションの商品 |
   | `popular` | 人気 | 注文数上位の商品 |

3. 保存

### 注意事項

- タグは半角小文字英字。`New` `seasonal-spring` などはマッチしません。
- 1 商品に複数タグを付けても表示されるバッジは 1 つだけ(優先度は上記表)。
- ストア通貨フォーマット連動: 管理画面 → 設定 → 一般 → ストア通貨 → 「フォーマットの編集」で `money_with_currency_format` 末尾の ` JPY` を削除してください(カート画面の `¥3,800 JPY` → `¥3,800` 表示のため)。

## 6. 補助ページの作成とテンプレート割当（Phase 3f）

`templates/page.delivery.json` `page.faq.json` `page.legal.json` `page.store-info.json` の 4 つの専用テンプレートをテーマ側で用意済み。各テンプレートは管理画面で「ページ」を作成して割り当てることで有効になります。

### 共通手順

1. 管理画面 → **オンラインストア → ページ → ページを追加**
2. **タイトル**(下表参照)を入力
3. **コンテンツ**は空欄でも可(テンプレートの各セクションが本体)。リード文を補足したい場合のみ入力
4. 右下 **テンプレート** で対応するテンプレートを選択
5. ページ右下 **検索エンジンリスティング → 編集 → URL とハンドル** を下表のハンドルに合わせる(初期値は日本語タイトルから自動生成された日本語ハンドルになるため、手動で英字に書き換える)
6. **公開状態 / Visibility** を「公開」に
7. 保存

### 4 ページの設定値

| ページ | タイトル | ハンドル | テンプレート |
|---|---|---|---|
| お届けについて | `お届けについて` | `delivery` | `delivery` |
| よくあるご質問 | `よくあるご質問` | `faq` | `faq` |
| 特定商取引法に基づく表記 | `特定商取引法に基づく表記` | `legal` | `legal` |
| アトリエのご案内 | `アトリエのご案内` | `store-info` | `store-info` |

### 注意事項

- **テンプレート一覧は live(発行中)テーマから取得されます**。`shopify theme dev` で開発テーマだけ最新化しても admin のドロップダウンには出ないため、`shopify theme push --theme=<live-theme-id>` で live を最新化してから admin 作業を行ってください。
- ハンドルを英字にしておくと、他ページからの相互リンク(`/pages/delivery` 等)が確実に動きます。
- アトリエのご案内ページの `image-with-text`（`shop_atelier`）セクションには `docs/seed-data/banners/11-store-exterior.png` を Files にアップロードのうえ設定済み（`templates/page.store-info.json` に `shopify://shop_images/11-store-exterior.png` を記述、`height: adapt`）。画像を差し替える場合は Files に新ファイルをアップロード → テーマカスタマイザ or 同テンプレートの `shop_atelier.settings.image` を更新。

## 7. フッターメニューに補助ページのリンクを追加する（Phase 3f）

テーマコード側ではメニュー項目を制御していません。リンク追加は admin の「メニュー」設定で行います。

### 手順

1. 管理画面 → **コンテンツ → メニュー**（Shopify が「メニュー」を「オンラインストア」配下から「コンテンツ」配下へ移動済み）
2. **フッターメニュー / Footer menu** を開く
3. 「メニュー項目を追加 / Add menu item」を 4 回繰り返し、以下を追加:

   | 名前 | リンク先(候補から選択 → ページ) |
   |---|---|
   | お届けについて | お届けについて(`/pages/delivery`) |
   | よくあるご質問 | よくあるご質問(`/pages/faq`) |
   | 特定商取引法に基づく表記 | 特定商取引法に基づく表記(`/pages/legal`) |
   | アトリエのご案内 | アトリエのご案内(`/pages/store-info`) |

   ※ リンク先候補は名前が似ていて取り違えやすい(「アトリエのご案内」項目に誤って `/pages/faq` を選んでしまう等)。追加後に各項目のリンク先 URL を必ず確認すること。

4. 並び順をドラッグで調整(推奨: お届けについて → よくあるご質問 → アトリエのご案内 → 特商法)
5. 保存

### メインメニュー(ヘッダー)への追加判断

- **お届けについて** や **よくあるご質問** はメインメニューにも入れて目立たせる派と、フッターのみで足りる派がある。Sweet Atelier では現状メインメニューが「アニバーサリー / 季節のケーキ / ギフト / 焼き菓子 / お問い合わせ」の 5 件で、これ以上増やすと SP で改行されるため **フッターのみ** が無難。
- どうしてもヘッダーに入れたい場合は「お問い合わせ」をフッター移動 → ヘッダーに「ヘルプ」グループを作って配下に「お届けについて」「よくあるご質問」をぶら下げるのも手。

## 8. ページ別 SEO description（meta-description）入力（Phase 4）

`layout/theme.liquid` で `page_description` (admin 入力) → `settings.brand_description` の優先順で `<meta name="description">` を出力します。`brand_description` 「季節と素材を映す、小さなケーキのアトリエ。」が全ページの fallback として使われるため、admin で何も入力しなくても meta は必ず出ます。

OGP / Twitter Card の `og:description` / `twitter:description`（`snippets/meta-tags.liquid`）も `page_description` → `shop.description` → `settings.brand_description` → `shop.name` の順で fallback します。admin にメタディスクリプションを入力すれば OGP も自動で揃います。

ただし **ページ毎に固有文言を出した方が SEO・CTR は強くなります**（特にホーム / 補助 4 ページ / コレクション）。下記の通り入力推奨です。

### 共通手順（admin → ページ / コレクション / ホーム）

1. 管理画面 → 対象ページを開く
2. 末尾の **検索エンジン表示 / Search engine listing → 編集**
3. **メタディスクリプション / Meta description** に下表の文言を入力（120〜160 文字目安）
4. 保存

### 推奨文言（Sweet Atelier ベース、デモ用）

| ページ | URL | メタディスクリプション |
|---|---|---|
| ホーム（オンラインストア → 環境設定 → タイトルとメタディスクリプション）| `/` | 季節と素材を映す、小さなケーキのアトリエ。アニバーサリー・季節のケーキ・ギフト・焼き菓子を全国へ冷凍配送。 |
| お届けについて | `/pages/delivery` | Sweet Atelier の配送について。冷凍便での全国配送、最短お届け日、定休日、解凍方法をご案内します。 |
| よくあるご質問 | `/pages/faq` | キャンセル・お届け日変更・アレルゲン・ギフトオプション等、お問い合わせの多いご質問にお答えします。 |
| 特定商取引法に基づく表記 | `/pages/legal` | 特定商取引法に基づく表記。販売事業者・所在地・連絡先・支払方法・返品交換ポリシー等を記載しています。 |
| アトリエのご案内 | `/pages/store-info` | Sweet Atelier の所在地・営業時間・ご連絡先。アトリエでの受け取り、店頭販売についてもご案内します。 |

### 注意事項

- **ホームのメタディスクリプションは admin の場所が異なります**: オンラインストア → 環境設定 → 「タイトルとメタディスクリプション」セクション内の「メタディスクリプション」欄
- 商品ページ（PDP）は `product.description` が自動で `page_description` に入るため、商品説明本文を充実させれば admin での個別入力不要
- コレクションページも `collection.description` 優先 → fallback で brand_description が出る
- 文言は **120〜160 文字** を目安に（Google 検索結果での見切れ回避）。短すぎても長すぎても SEO 効果が落ちる
- OGP/Twitter Card にもこの文言が反映される（`og:description` / `twitter:description`）。SNS シェア時のプレビュー文になるので、admin 入力推奨

## 9. アレルゲン情報の登録（Phase 5a）

商品ページ（PDP）の「アレルゲン情報」行の中に、構造化されたアレルゲン表（アレルゲン名 / 区分）を表示する。
テーマは **Shopify 標準の「アレルゲン情報」カテゴリーメタフィールド**（ケーキ系カテゴリーに最初から付いてくる欄）を読む。
「区分」（特定原材料 / 推奨表示）はテーマ側で日本の食品表示法の固定リストから自動判定する（メタフィールド側で持つ必要なし）。

### 9-1. 各商品の標準「アレルゲン情報」カテゴリーメタフィールドに入力（メイン作業）

各商品の編集画面 → 下の方の **「カテゴリーメタフィールド」** セクション →「アレルゲン情報」欄に該当アレルゲンを追加（クリックで候補から選ぶ。チップ表示になる）。

| 商品 | 「アレルゲン情報」に入れる値（この順で並べる） |
|---|---|
| 苺のショートケーキ | 卵, 乳, 小麦 |
| クラシックショコラ | 卵, 乳, 小麦, 大豆 |
| 桜と苺のタルト | 卵, 乳, 小麦, アーモンド |
| アトリエクッキー缶 | 卵, 乳, 小麦, アーモンド, くるみ, 大豆 |
| アニバーサリーホールケーキ | 卵, 乳, 小麦 |

> - 同じ「カテゴリーメタフィールド」セクションにある **「フレーバー」「小麦粉・穀物の種類」は本デモでは使わない**（空欄のままで OK）。フレーバーはアレルギーとは無関係の味系統タグ。
> - テーマは候補の **表示ラベル**を読み、「卵・乳・小麦・えび・かに・そば・落花生・くるみ」に一致するものを **特定原材料**、それ以外を **推奨表示** として表の「区分」列に出す（食品表示法の 8 品目）。Shopify のラベル表記が 8 品目と微妙に違う場合（例: 「クルミ」とカタカナ等）は自動的に「推奨表示」側に入る — デモ上は許容範囲。
> - 表に出る順序は、この欄に並べた順になる。
> - 参考: 推奨表示 20 品目 = アーモンド・あわび・いか・いくら・オレンジ・カシューナッツ・キウイフルーツ・牛肉・ごま・さけ・さば・大豆・鶏肉・バナナ・豚肉・まつたけ・もも・やまいも・りんご・ゼラチン。

### 9-2. （任意）コンタミネーション注記用のメタフィールドを作る

「同一施設で○○を含む製品を製造しています」のような注記を表の下に出したい場合のみ。スキップ可（その場合は注記行が出ないだけ）。

管理画面 → **設定 → カスタムデータ → 商品 → 定義を追加**

| 名前 | 名前空間とキー | タイプ |
|---|---|---|
| コンタミネーション注記 | `custom.allergen_contamination` | 複数行テキスト |

作ったら各商品の編集画面 → 「メタフィールド」セクションで入力。デモ用の値（任意）:

| 商品 | `custom.allergen_contamination` |
|---|---|
| 苺のショートケーキ | 同一施設でそば・落花生・えび・かに・くるみを含む製品を製造しています。 |
| クラシックショコラ | 同一施設でそば・落花生・えび・かに・くるみを含む製品を製造しています。 |
| 桜と苺のタルト | 同一施設でそば・落花生・えび・かに・くるみを含む製品を製造しています。 |
| アトリエクッキー缶 | 同一施設でそば・落花生・えび・かにを含む製品を製造しています。 |
| アニバーサリーホールケーキ | 同一施設でそば・落花生・えび・かに・くるみを含む製品を製造しています。 |

> デモなら 1 商品（苺のショートケーキ）だけ入れて「こういう注記も出せます」を見せれば十分。残りは空欄でよい。

### 9-3. （任意・上級）標準フィールドを使わず独自に持ちたい場合

標準カテゴリーメタフィールドを使いたくない／自前で並びを完全管理したい場合は、`custom.allergens`（メタオブジェクト「アレルゲン情報」への参照・**リスト**）を作って各商品で設定すると、テーマはそちらをフォールバックとして読む（標準フィールドが空のときのみ）。本デモでは 9-1 の標準フィールドで十分なので通常は不要。

### 9-4. テーマ側の設定（設定済み）

`templates/product.json` の `tab-allergen` ブロックで `show_allergens: true` を指定済み。
テーマカスタマイザでも 商品テンプレート →「アレルゲン情報」行 →「アレルゲン表を表示する」チェックで切り替えられる。
他の `collapsible_tab` 行でも同チェックを ON にすれば同じ表が出る。

### 9-5. （任意）コレクションでアレルゲンを絞り込み

「検索と発見」アプリ → **フィルター** → 標準の「アレルゲン情報」メタフィールドを追加すると、コレクションページの絞り込みに出る（テーマ側の `snippets/facets.liquid` は metafield フィルターを汎用的に描画するため変更不要）。本デモでは絞り込みは任意。

### 注意事項

- アレルゲン表のスタイルは `assets/component-allergen-table.css`、描画は `snippets/product-allergen-table.liquid`（読む順: 標準 `shopify.allergen-information` → なければ `custom.allergens`）
- アレルゲン未設定の商品は「アレルゲン情報は現在準備中です」と表示される（エラーにはならない）
- 商品カードのバッジ「アレルゲン情報あり」はアレルゲンが設定されている商品にのみ出る（ただし `人気 / 季節限定 / 新商品` バッジが優先）
- `show_allergens` チェックのラベルは、20 言語の schema 翻訳同期コストを避けるため `t:` キーではなくセクション schema に直接日本語文字列で記述している（known-issues.md 参照）

## 10. 季節商品の販売期間メタフィールド（Phase 5c）

商品ページ（PDP）に「販売は MM/DD まで（残り N 日）」バナーを出し、商品カードのバッジに残り日数を載せ、`/collections/seasonal` の上部に販売中の季節商品リストを出すための設定。テーマは商品の **`custom.sale_start` / `custom.sale_end`（日付メタフィールド）** を読む。

### 10-1. メタフィールドを定義する（1 回だけ）

管理画面 → **設定 → カスタムデータ → 商品 → 定義を追加**

| 名前 | 名前空間とキー | タイプ |
|---|---|---|
| 販売開始日 | `custom.sale_start` | 日付 |
| 販売終了日 | `custom.sale_end` | 日付 |

両方とも **タイプ = 日付**（Date、時刻なし）で作成。

### 10-2. 季節商品に値を入れる

`seasonal` タグが付いている商品（桜と苺のタルト等）に対し、各商品の編集画面 → 「メタフィールド」セクションで入力。デモ値の例（年は適宜現在の年に合わせる）:

| 商品 | `custom.sale_start` | `custom.sale_end` |
|---|---|---|
| 桜と苺のタルト | 2026-03-01 | 2026-05-31 |

> - 1 商品でも入っていれば PDP のバナーと `/collections/seasonal` の案内枠が出る。デモは最低 1 商品で十分。
> - 両方とも空にすると、その商品では何も表示されない（PDP バナーも非表示、カードバッジは従来通り「季節限定」のみ）。
> - 期間中 → 「販売は MM/DD まで・残り N 日」。期間外（終了後） → PDP は「販売終了」、カードバッジからは「季節限定」が消えて優先度が次の `new` / `アレルゲン情報あり` に移る。
> - `sale_start` を未来日付にすると「MM/DD から販売開始・あと N 日」と出る。

### 10-3. テーマ側の設定（設定済み）

- `templates/product.json` の `block_order` に `sale-period` を含めてあり、PDP の価格直下にバナーが出る。テーマカスタマイザの 商品テンプレート → 「販売期間バナー」ブロックで強調表示のしきい値（残り日数）を 1〜30 日で変更できる（既定 7 日）。
- `/collections/seasonal` は `templates/collection.seasonal.json` で上書きされ、グリッドの上に「季節商品 販売中バナー」セクションが乗る。テーマカスタマイザで見出し・サブテキスト・最大表示件数（既定 6）を編集できる。

### 注意事項

- メタフィールドは「日付」型を使う（「日付と時刻」型でも動くが、表示は日付粒度。時:分:秒のカウントダウンは行わない — Shopify Storefront のキャッシュとの相性が悪いため `docs/known-issues.md` §12 参照）
- 期間判定はストアフロントのリクエスト時刻（Shopify edge の現在時刻）で行うため、日付の境界は店舗タイムゾーンに対し最大数時間ズレることがある（学習デモでは許容）
- `sale_period` ブロックのラベル「販売期間バナー」は、20 言語の schema 翻訳同期コストを避けるため `t:` キーではなく直接日本語文字列で記述している（`docs/known-issues.md` §1 参照）

## 11. 検索・フィルター・並べ替え（Phase 8）

コレクション／検索結果ページの**絞り込み（フィルター）・並べ替え（ソート）・予測検索**を整える。
テーマ側（`snippets/facets.liquid`）は `collection.filters` / `search.filters` を**汎用的に描画する**ため、どのフィルターを出すかは Shopify 公式アプリ **「検索と発見 / Search & Discovery」** で制御する。テーマコードの追加は不要（ソート有効化のみ済み、後述 11-3）。

### 11-1. 「検索と発見」アプリのインストール

1. 管理画面 → **アプリ / Apps** → 「Shopify App Store」検索 → **Search & Discovery**（Shopify 公式・無料）をインストール
2. インストール後、管理画面左メニューに「検索と発見」が追加される
3. タブ構成: **フィルター / 検索 / おすすめ商品 / 分析**

### 11-2. フィルターの設定（コレクション絞り込み）

「検索と発見」→ **フィルター / Filters** → 「フィルターを追加 / Add filter」で以下を追加。コレクションページ左（`filter_type: "vertical"`）と検索結果ページ上（`horizontal`）に自動で出る。

| フィルター元 | ソース | ラベル例 | 用途 |
|---|---|---|---|
| 価格 | 標準（Price） | 価格 | 価格帯スライダー／レンジ |
| 商品タグ | 標準（Tag） | タグ | `new` / `seasonal` / `popular` 等で絞り込み |
| コレクション | 標準（Collection） | カテゴリー | 定番／季節／アニバーサリー等 |
| アレルゲン情報 | メタフィールド（`shopify.allergen-information`） | アレルゲン | §9 で登録した標準アレルゲンメタフィールド |
| サイズ | バリアントオプション（`サイズ`） | サイズ | §1 の号数バリアント |

> - フィルターの**表示順・ラベル名**もこのアプリ内でドラッグ／編集できる（テーマ側の変更不要）。
> - アレルゲンでの絞り込みは §9-5 のとおり**任意**。メタフィールドフィルターは商品にメタフィールドが入っている場合のみ選択肢に出る。
> - タグでの絞り込みを使う場合、表示ラベルは生のタグ文字列（`new` 等の英小文字）になる。日本語ラベルにしたいときはアプリ側でフィルター値の表示名を上書きするか、商品タグ自体を日本語化する運用にする（デモでは英小文字タグのままで可）。

### 11-3. 並べ替え（ソート）の有効化（テーマ側・設定済み）

- `templates/collection.json` の `main-collection-product-grid` で **`enable_sorting: true`** に設定済み（おすすめ／新着／価格の高い順・安い順／名前順などの並べ替えドロップダウンが出る）。
- `templates/search.json` も `enable_sorting: true`。
- 並べ替えの選択肢自体は Shopify 標準（コレクションの「商品の並べ替え」設定とストアフロントのソートパラメータ）に従う。アプリ側の追加設定は不要。

### 11-4. 検索（予測検索・シノニム・リダイレクト）

「検索と発見」→ **検索 / Search**：

- **シノニム / Synonyms**: 表記ゆれ・別名を同義として扱う。デモ推奨例:
  - `ショートケーキ` ⇔ `苺` ⇔ `いちご`
  - `ショコラ` ⇔ `チョコ` ⇔ `チョコレート`
  - `焼き菓子` ⇔ `クッキー` ⇔ `ギフト缶`
- **検索結果のリダイレクト**: 特定キーワード（例: `送料`）を `/pages/delivery` に飛ばす等。任意。
- 予測検索（ヘッダー検索の入力中サジェスト）はテーマ側（`predictive-search`）で既に有効。商品・コレクション・ページ・クエリ候補が出る。

### 注意事項

- **アプリ未インストールでも壊れない**: フィルターが 1 つも定義されていない場合、コレクションページの絞り込みカラムは出ない（グリッドのみ）。ソートは標準なので出る。
- **メタフィールドフィルターの前提**: アレルゲン絞り込みは §9 の標準アレルゲンメタフィールドが各商品に入っていることが条件。空ならフィルター候補に現れない。
- **`templates/collection.json` / `search.json` は自動生成ファイル**: admin のテーマエディタで上書きされる可能性がある。ローカルで編集したら `shopify theme push` で反映し、admin 側で同テンプレートを触った場合は `shopify theme pull` 前にローカル差分の退避を確認すること（`docs/known-issues.md` 参照）。
- **アプリ設定はテーマに依存しない**: 「検索と発見」の設定はストア（admin）側に保存されるため、テーマを切り替えても・push しても消えない。
