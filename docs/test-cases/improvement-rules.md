# 改善ルール（テスト検証から得た知見）

テスト・検証の過程で見つけた「再発防止のための一般化された知見」を蓄積する。
個別のバグ修正（git 履歴に残る）ではなく、**次のテスト項目書・実装に反映すべきルール**を書く。

## 使い方

- 検証で「これは他でも踏みそう」と気づいたら 1 行ルールとして追記する
- ルールごとに「きっかけ（どのテストで気づいたか）」と「適用先（どの項目書/コードに効くか）」を残す
- 新しい phase の項目書を起こすときは、ここを読んで該当チェック項目を足す

## ルール一覧

### R-001 カード上のインタラクティブ要素はリンクのスタッキングを回避する
- **きっかけ**: TC-9B-01（ウィッシュリストのハート）。カード全体リンクの `::after` がハートを覆い、クリックが遷移に奪われていた（Phase 9b で修正）
- **ルール**: カード内に独立操作する要素を置くときは `card-wrapper` 直下に配置し、リンクの `::after` オーバーレイより上の重ね順を確保する
- **適用先**: 商品カードに後付けする全 UI（お気に入り・クイック追加等）。新規カード系項目書に「カードリンクに奪われずトグルできる」を入れる

### R-002 二重ロードされうるカスタム要素 JS は再宣言ガードを入れる
- **きっかけ**: TC-9B-06。`wishlist.js` がブラウザの戻る/進む等で二重評価され `const` 再宣言エラーが出た
- **ルール**: `customElements.define` を伴う JS は IIFE で包み、`customElements.get('...')` の存在チェックで二重定義を防ぐ
- **適用先**: 新規に追加する全 Web Components 系スクリプト。項目書に「二重ロードでコンソールエラーが出ない」を入れる

### R-003 reveal-on-scroll があるページの fullPage スクショは reducedMotion で撮る
- **きっかけ**: Phase 3→4 のスクショ改善。ファーストビュー外セクションが `opacity:0.01` 待機のまま空白で写っていた
- **ルール**: `scripts/capture-screenshots.mjs` は `reducedMotion: "reduce"` 指定でスクロール待機を無効化する。証跡スクショはこの方式で撮る
- **適用先**: 全 phase の証跡キャプチャ。`docs/known-issues.md §9` と同根

### R-004 localStorage 依存機能は「空状態」と「取り違え」を必ず項目化する
- **きっかけ**: TC-9A-03（履歴空でセクション非表示）/ TC-9B-02（handle が全件 "all" になる取り違え）
- **ルール**: `localStorage` でリストを持つ機能は ①空のときの表示 ②キーごとの値の正しさ ③上限/押し出し の 3 点を必ずテストする
- **適用先**: 最近見た商品・ウィッシュリスト・送料シミュレーターほか状態保持系の項目書

### R-005 状態を共有する連続キャプチャは「最終状態」を明示してから撮る
- **きっかけ**: TC-9B-05 の証跡。同一ブラウザ context（localStorage 共有）でカードを ON にした後、PDP で同じ商品をクリックすると OFF に戻り、「お気に入りに追加」（未追加）が写ってしまった
- **ルール**: トグル要素を撮るときは「クリックする」のではなく「目的の状態にする」。`aria-pressed` 等の現在状態を読み、目的状態でなければ操作する。前のステップが残した localStorage を引きずる前提で書く
- **適用先**: `scripts/capture-*.mjs` のトグル系ショット全般。状態保持系機能の証跡キャプチャ
